# Translation

The app speaks English and German, with "du" (owner); English is the fallback. Scope: every page of
the app with its helpers (the Track pages: rule `i18n-track`) and the HTML report (rule `charts`),
so `i18n_check.TRANSLATED` holds every module of `ui/` and `report/` (by glob, a new one too), and
the words of the model, of the ledger (`budget.said`, rule `ledger`), of the goal seek,
`result.unit` and the series (`series.SERIES`). English stays: the CLI with the console summary
(`report.console_table`), input errors (`InputError` lines, the model's messages in a form,
`datadir.check_born`; a stream row that the model refuses is said at its grid by the type of the
check, `ui.refusals`), the source notes of the series (by their terms), the manual, YAML keys (in
the files and in code spans), user data (names, notes, phase labels, categories, scenario stems:
never through `_()`; a new plan writes them in the language of the session, `datadir.NAMES`, rule
`first-run`), `engineer` (`starter` is German in either language, rule `examples`), the revision
log (`ui.source` keeps the English page title).
Numbers and dates keep the one format in both languages (owner: rule `money`, `14.1%`, `1.234.567
€`, ISO months; the points estimate of the start page too, `9.24`). Streamlit 1.65 and plotly have
no locale for their words (the grid toolbar, `Add row`, the file uploader, `Press Enter to apply`,
the date picker, the modebar): they stay English (selectors of `page.css`).

## Mechanism

- gettext with Babel: the English text is the msgid,
  `src/dagobert/locale/de/LC_MESSAGES/dagobert.po` the one catalogue (package data; no `.mo`, no
  `.pot` in git). `i18n.translations` compiles it in memory once per process (`mofile.write_mo`,
  without the fuzzy entries).
- `i18n._`, `ngettext` and `pgettext` translate at call time into the language of a `ContextVar`
  (default `en`): each session runs in threads of its own, so no global and no `gettext.install`.
  `main.py` calls `i18n.activate(ui.language())` first in every run. `dagobert run --lang en|de`
  (`DAGOBERT_LANG`; `cli._language`: a locale too, `de_DE.UTF-8`, through `i18n.negotiate`) is a
  parameter of `cli._render`, no run option: it writes the report inside `i18n.use(lang)`
  and prints the console summary outside it, so the summary stays English though it shares
  `report.summary_columns`; `write_html` sets `<html lang>`, the tab labels and their URL hash
  follow the language.
- A script thread starts at `en`. A callback runs before `main.py`, so it moves state and makes no
  text (`ui.tell` takes text of the run). A dialog (a fragment) reruns alone, without `main.py`, in
  a new thread (`AppSession._create_scriptrunner`; Python 3.14 starts a thread with an empty
  context): without `i18n.activate(ui.language())` first it spoke English (checked in Chrome),
  so every dialog function starts with it (`rename._dialog`, the file actions of
  `fileactions`). The title of a dialog comes per call, `st.dialog(_("Rename"))(_dialog)(…)`: a
  decorator runs at import, in no session.
- A constant keeps its English msgid marked `N_` (the identity, for the extraction), and `_()`
  translates it where it shows, also one outside `ui/` (`series.SERIES`: titles, uses, licences);
  a word that a module outside `ui/` makes for a page and the CLI says `_()` there (`series.gap`,
  `transfer.Preview.notes`): the CLI runs in `en`. `NP_(context, …)` marks one in a context: a
  sprintf format with words (`NP_("sprintf", "%.0f months")`, `sliders.Unit.format`) stays English
  in its dataclass and is said by `pgettext("sprintf", …)` at `st.slider(format=)` and `printf`
  (`i18n_check.SPRINTF` knows the padding `'c` of `GROUPED`). A widget key, an option value, a cache
  key, a page key or a stored source never holds translated text (rule `ui`); a process cache
  (`st.cache_*`, `functools.cache`) holds none either, as it serves every session: a run holds
  data (markers, `anatomy.drivers` by kind and name), `seek._dial` a `goalseek.NoChange`, and
  `Lever` and `Dial` compare without their words (`test_a_language_switch_runs_nothing_again`).
- Named placeholders, `str.format` after the call: `_("Born {day}, age {age}.").format(...)`.
  Never `%` (Babel flags `5% chance` as python-format) and no f-string or `.format` inside the call
  (ruff `INT`, which checks the first argument only: `pgettext("c", f"…")` slips through). A msgid
  holds no HTML and no plotly template: the code composes them around it.
- Whole sentences, one msgid per use: no sentence from fragments, no `.lower()` or `.capitalize()`
  of a translation (German nouns keep their capital: so `About {label}` keeps the capital of the
  label in English too). A list of values goes through `babel.lists.format_list` (`{first} and
  {then}` where English joins more than two with `and`, `ui.joined`), a date in words through
  `babel.dates.format_date` with a translated pattern (`_("d MMMM y")`, German `d. MMMM y`: `20. Mai
  1986`), both with `locale=i18n.language()`.
- `ngettext` with `{n}` for a count (German and English: `nplurals=2`); `pgettext` where one English
  word takes two German ones (`pgettext("navigation", "Plan")`: `Planen`, a section, not a plan;
  `condition`: `at {age}` of a sale `ab 60`, of a value `mit 67`; `amount`: `all` of a repayment
  `alles`, of scenarios `alle`; `slider`: `Rebalance every` without the `(Monate)` of its field).

## The model and the shared helpers

- `i18n_check.MAPPING` sends `model/*.py` to the Babel method `i18n_check.schema`
  (`module:function`), which imports the module (and Streamlit, only to extract) and yields
  `ui.fields.messages` of each model that it defines, by the functions that show them: the
  descriptions (`gridcolumns.oneline`), the label of a key that no page names (`model.base.named`:
  `Cash buffer months`, `AfA`), each key in the context `key` (`gridcolumns.keyword`: English the
  key itself, as a grid heads its column and the save guard names it; German a word) and the options
  in words (`Titled`). The model stays English; its descriptions hold no braces (the help formats
  them), and a page doubles those of user data in an `about` (the phase label of
  `scenario_overrides.scale_form`).
- `fields.Field` and `gridcolumns.Column` keep the English of the model and the page (`about`,
  `named`, `more`, `term`, `Column.label`), so a module constant or a cache may hold them
  (`assumptions.FIELDS`, `overridegrids.settable`); `label`, `help` and `Column.header` say
  them in the language of the session where they show (`gridcolumns.said`). `forms.Form`
  translates the words of a page (labels, nulls, terms, helps, choices, `When.why`, plain words),
  `Table` its titles and helps; a phase label as a header, a stem, a name and an option value stay
  as written. A placeholder names its source as written (`3 from base`), but `the name`.
- A line of the save guard (owner) names a field by its key path, each key by `keyword`, an entry,
  a row number and a name as written: English keeps the keys (`returns equity mean`), German
  `Renditen equity Mittelwert`; a grid cell by `Table.names` (`gridcolumns.names`, a column per key
  as its header); `guard.Change.key` keeps the English (rule `save-guard`). The roll forward keeps
  its keys.
- `save.changed_at` and the days of `Changes since` (`ui.day_said`, `Day.said`) name
  the page of a source in words (`ui.page_said`: `um 14:03 auf der Seite Annahmen: Markets`), the
  action as written. `save.reason` says `BusyError`, `ReadOnlyError` and `ConflictError` in
  German by their type, any other error as written; every `Not saved:` takes it.
- A language switch draws every dynamic grid anew: Streamlit 1.65 keys a dynamic `st.data_editor` by
  its column config, also with a key, and the new grid showed the rows without their unsaved edits
  while the guard still listed them. So `ui.chose` carries the edits of the grids that
  `gridstate.drawn` notes (`edit_table`, the small grids of a form, the grids by id of the Overrides
  tab, the repayments of a sale) as `All columns` does (`gridstate.carry`; checked in Chrome and by
  `test_i18n` with `german.edited`, which sends the edits of a grid as a browser does); the Spend
  grid carries its own (rule `spend`).

## The language of a session

- `ui.language()`: `?lang=de|en` (tests and links; popped, so the switch can change it), the
  state of the switch (`ui.LANGUAGE`), the cookie `dagobert-lang` of an earlier choice (of the
  first request only), the language of the browser (`st.context.locale`), the `Accept-Language`
  tags by weight (`i18n.preferred`), English; each through `i18n.negotiate` (`de-CH` is `de`).
  `AppTest` sends no locale, header or cookie: the suite runs English.
- `ui.language_switch`: a segmented control at the end of the sidebar, drawn by `main.py` in the
  `finally` after the page, below the mode switch (rule `mode`), so also beside `The inputs do not
  load` and on the start page, whose sidebar has it alone. On a phone it folds with the sidebar; on
  the Explorer it follows the box `explorer-sidebar`, whose sticky strip and buttons end with it
  (rule `explorer`). Its label in both languages (`Sprache · Language`, `:material/translate:`)
  helps a viewer lost in one; its options are the codes, shown by their endonyms. A choice
  (`ui.CHOSEN`) writes the cookie (`ui.remember`) with a script (`SET_COOKIE`: 400 days, `path=/`)
  in every later run: Streamlit sets no cookie.
- A select box or a segmented control of ids shown by `format_func` keeps its choice over a switch
  and the runs after it (checked in Chrome as a desktop and a phone, both ways: the
  seek lever of the Explorer, the measure of the Overview, the scenario and `Amounts` of the Flows
  page). The browser sends the words that it shows, and Streamlit 1.65 reads them back to the id
  by the run before: `SessionState._call_callbacks` deserializes every widget before the script
  runs. `AppTest` cannot show it: it sends a select by its `format_func`, called after the run,
  against the options of that run, and when the words differ its next run raises ValueError
  (`Selectbox.index`). A test-only limit: check such a switch in a browser.
- The boot script of `main.py` sets `<html lang>` (hyphens, screen readers, Chrome's translate
  offer), again after a switch: its text changes, so Streamlit runs it again (rule `ui`).
- The navigation keys a page by its English title (`main.entry`, marked `N_`) and shows `_(title)`;
  the sections are `_("Track")`, `pgettext("navigation", "Plan")`, `_("Setup")`. URL paths stay.
  The owner's names: Overview `Übersicht`, Assets `Vermögen`, Spend `Ausgaben`, Data `Daten`,
  Assumptions `Annahmen`, Scenarios `Szenarien`, Export and import `Export und Import`, Features
  `Funktionen` (the design of the mode); Explorer,
  Cashflows, Flows and Snapshot stay English (their msgstr is the msgid).

## Catalogue and checks

- `uv run python scripts/i18n update` extracts what the code marks (`i18n_check.KEYWORDS`) and the
  model shows (`i18n_check.extract`, the Babel methods of `i18n_check.MAPPING`) into the `.po`
  (`Catalog.update`, sorted by file, no line numbers): a new message comes empty, a changed one with
  the old German marked `#, fuzzy`, a dropped one goes. Write the German of the empty ones, confirm
  the fuzzy ones. `i18n_check.write` empties `Report-Msgid-Bugs-To` and `Last-Translator` (Babel's
  `EMAIL@ADDRESS`).
- `uv run python scripts/i18n check` (the pre-commit hook `i18n-check` on `src/` and the script, a
  step of CI) and `tests/test_i18n.py` run `i18n_check.problems` (every msgid of the code is in the
  catalogue, translated, not fuzzy; none that the code lacks, no obsolete `#~`; the same `{fields}`
  per plural form, the same `%` conversions in the context `sprintf`, the same backtick spans: a
  YAML key stays, the name of a button may take its German from the catalogue, `Rename` as
  `Umbenennen`) and `i18n_check.lint` (in the modules of `TRANSLATED`, a Streamlit call of `SHOWN`
  shows no literal with words and no constant that the module marks `N_` outside `_()`, also in an
  f-string or before `.format`: its text, `label`, `help`, `placeholder`, `caption`, `body`; an icon
  is no word). The lint reads one module: English in a variable, an attribute or a constant of
  another module passes it, only the German render tests catch it. A change of a module of
  `TRANSLATED` ships its German in the same commit.
- `tests/german.py`: `leaks` (a text that equals an English message without a context whose German
  differs; with `inside` also one or more words inside a text), `words` (the texts of an `AppTest`
  run), `report_words` (the text, the tips and the words of the figures of an HTML report: the lint
  sees no HTML), `ACTIVATE` (a page drawn alone takes the language first, as `main.py`) and
  `edited` (the edits of a grid as a browser sends them, by the internals of `AppTest` in Streamlit
  1.65: check it after an upgrade). A German
  report shows no leak but its data and the terms of its tips (`test_report`), `run --lang de`
  writes it with the console summary in English (`test_cli`), and the check of rule `charts` runs
  in German too. The start page
  renders with `?lang=de` as a desktop and a phone without a leak but the data of the examples, the
  date of birth in German, and the switch goes back to English (also `<html lang>`) and writes the
  cookie. `test_pages_render` draws every page also in German, without a leak, also inside a text
  (`test_the_pages_show_no_english_in_german`), and the helpers and the Explorer speak German
  (`test_the_shared_helpers_speak_german`, `test_the_explorer_speaks_german`); so do the pages
  Cashflows, Spend and Flows
  (`test_the_cash_pages_speak_german`) and those of `Setup` with a dialog and an import preview
  (`test_the_setup_pages_speak_german`). `app-check` of a translated page runs in German too
  (`?lang=de`), its switch with no error. Units in parallel worktrees write disjoint regions of the
  `.po` (sorted by file): an overlap merges as the union, then `update`.
